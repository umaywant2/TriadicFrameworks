# 🧬 TriadicFrameworks Spine Module  
The **Spine** is the structural backbone of the TriadicFrameworks canon.  
It provides the *overlay system*, *continuity mechanics*, *module graph*, and *schema definitions* that allow all RTT/1 modules to align under a unified substrate.

The Spine is not a content module — it is an **infrastructure module**, defining how content modules relate, propagate, and maintain coherence across the full TriadicFrameworks ecosystem.

---

## 🌐 Purpose of the Spine
The Spine provides:

- A **canonical overlay system** (structural, drift, coherence, substrate, dimensional, domain, clarity)
- A **module graph** describing cross‑module relationships
- A **schema layer** defining how modules are structured
- A **continuity kernel** for RTT/1 alignment
- A **navigation and atlas layer** for UI and agentic traversal

Every TriadicFrameworks module can be projected through the Spine overlays to reveal its structure, drift, coherence, substrate alignment, dimensional mechanics, domain placement, and clarity layer.

---

## 🧩 Overlay Set (8 Overlays)
Each overlay has two files:  
- The **overlay document** (`*_overlay.md`)  
- The **overlay module manifest** (`*_overlay_module.json`)

### 1. **Structural Overlay**
- `structural_overlay.md`  
- `structural_overlay_module.json`  
Defines the module’s structural primitives, operators, and canonical shape.

### 2. **Drift Overlay**
- `drift_overlay.md`  
- `drift_overlay_module.json`  
Captures drift vectors, regime shifts, and continuity deviations.

### 3. **Coherence Overlay**
- `coherence_overlay.md`  
- `coherence_overlay_module.json`  
Measures coherence across operators, regimes, and module boundaries.

### 4. **Substrate Overlay**
- `substrate_overlay.md`  
- `substrate_overlay_module.json`  
Maps substrate alignment, substrate dependencies, and substrate propagation.

### 5. **Dimensional Overlay**
- `dimensional_overlay.md`  
- `dimensional_overlay_module.json`  
Defines dimensional mechanics, L4 continuity, and cross‑dimensional operators.

### 6. **Domain Overlay**
- `domain_overlay.md`  
- `domain_overlay_module.json`  
Places the module within the TriadicFrameworks domain lattice.

### 7. **Clarity Overlay**
- `clarity_overlay.md`  
- `clarity_overlay_module.json`  
Provides clarity vectors, validator pulses, and the clarity‑equation alignment.

### 8. **Atlas / App Layer**
- `app/README.md`  
- `app/triadic_atlas.html`  
UI layer for navigating overlays and module projections.
