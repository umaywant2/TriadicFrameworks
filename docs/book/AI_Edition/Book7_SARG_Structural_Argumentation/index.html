SARG Structural Argumentation

Defines SARG as a formal framework for constructing, evaluating, and defeating arguments using structural properties. Arguments are modelled as structures; validity is determined by constraint satisfaction and invariant preservation — not by propositional truth.

Invariants

INV-SARG-001
Argument Integrity
∀n ∈ N_A: reachable(n, root(A), R_A)
Every argument node must be reachable from the argument's root claim via declared relations. Unreachable nodes are structurally phantom — they cannot contribute to or defeat the argument.
SARG-Ν · construct
INV-SARG-002
Warrant Necessity
∀(c,e) ∈ N_A²: support(c,e) → ∃w ∈ N_A: warrant_bridge(w,c,e)
Every claim-evidence pair connected by a support relation requires at least one explicit warrant node bridging them. Unwarranted support relations are structurally invalid and are reclassified by SARG-Ω as surface assertions.
SARG-Ω · warrant
INV-SARG-003
Defeat Completeness
defeat(D,A) → ∃x ∈ {N_A ∪ R_A ∪ C_A}: targets(D,x)
A defeat of an argument must target at least one structural component — a node, relation, or constraint. Surface-level objections that fail to target a structural component are reclassified as parallel assertions, not defeats.
SARG-Δ · defeat
INV-SARG-004
Reflexive Prohibition
¬∃path ⊆ R_A: path(root(A), root(A)) without independent_evidence_node
An argument cannot provide structural support for its own root claim without passing through an independent evidentiary node. Circular arguments that route back to root without independent provenance are structurally self-defeating.
SARG-Ρ · evaluate

Argument Structure

Argument Tuple

A = ⟨N_A, R_A, C_A, root(A)⟩

Where N_A = node set, R_A = relation set, C_A = constraint set, root(A) = root claim node. SARG soundness ≠ propositional truth — they are orthogonal properties.

Node Types (NT-001 – NT-005)

IDLabelDescription
NT-001ClaimA structural assertion to be supported. The root(A) is always NT-001. Claims require at least one support relation from an Evidence node.
NT-002EvidenceAn independently-sourced structural datum. Independence condition: provenance(n_i) ∩ derivation_closure(root(A)) = ∅.
NT-003WarrantA structural rule that bridges a claim-evidence pair. Required by INV-SARG-002 for every support relation.
NT-004QualifierBounds the scope or confidence of a claim. Attached via RT-A-003 (Qualification). Does not defeat — it restricts.
NT-005RebuttalA counter-claim that targets a specific node or relation. Must pass INV-SARG-003 to qualify as structural defeat.

Relation Types (RT-A-001 – RT-A-004)

IDSymbolLabelDescription
RT-A-001→SupportDirected support from evidence/warrant to claim. Requires NT-003 bridge per INV-SARG-002.
RT-A-002⊥ContradictionStructural contradiction between two nodes. Triggers SARG-Δ defeat evaluation.
RT-A-003⊗QualificationScope-bounding relation from NT-004 to a claim or support path.
RT-A-004⊢Warrant BridgeExplicit warrant relation linking NT-003 to a claim-evidence support pair.

Defeat Types

DT-001
Node Defeat
Targets a specific argument node n ∈ N_A. Defeat is valid if the node is reachable and the defeat argument satisfies INV-SARG-003. Removes the node and all relations incident to it.
DT-002
Warrant Defeat
Targets a warrant node (NT-003). Severs the warrant bridge, rendering the corresponding claim-evidence support relation unwarranted. Triggers INV-SARG-002 re-evaluation.
DT-003
Relation Defeat
Targets a specific relation r ∈ R_A directly. Severs the relation without removing either endpoint node. May cascade to isolation violations under INV-SARG-001.
DT-004
Constraint Defeat
Targets a constraint c ∈ C_A. Demonstrates the constraint itself is structurally invalid or contradictory. Recursive — a constraint defeat may trigger further defeat evaluation. Max recursion depth: 3.
⚠ Recursive — max depth 3. Depth exhaustion is defeat failure mode DFM-004.
DT-005
Undercutting Defeat
Targets the applicability of a warrant to a specific claim-evidence pair, without denying the warrant's general validity. The warrant remains valid for other pairs; its application here is blocked.

Evaluation Gates

EG-001
Integrity
All nodes in N_A are reachable from root(A) via R_A. Checked by SARG-Ρ. Gate fails → argument rejected as malformed (INV-SARG-001 violation).
EG-002
Warrant Coverage
Every support relation has at least one warrant bridge. Checked by SARG-Ω. Gate fails → unwarranted support relations flagged; argument is defeasible at minimum.
EG-003
Defeat Completeness
All proposed defeats target structural components. Checked by SARG-Δ. Surface objections that fail this gate are reclassified as parallel assertions — not defeats of the argument.
EG-004
Reflexive Prohibition
No path in R_A routes from root(A) back to root(A) without passing through an independent evidence node. Checked by SARG-Ρ. Circular arguments fail this gate — they are structurally self-defeating.
EG-005
Constraint Satisfaction
All structural constraints in C_A are satisfied by the argument configuration after defeat evaluation. Checked by SARG-Σ. The final gate before sarg_result is emitted.

Phase Cycle

Phase sequence: init → construct → warrant → defeat → evaluate → catalogue

P-1
init
— (no ops)
Load all 4 dependency modules in order: book1_fft → book3_sd → book5_tel → book6_grl. Assert session context. Confirm QMROOT 0D. Initialize argument slot as empty. GRL regime_status_report fields are prepared as typed Evidence node inputs.
P-2
construct
SARG-Ν
Construct all argument nodes. Assign node types NT-001–NT-005. Verify root(A) exists and is NT-001. Check reachability for all nodes. Record N_A and R_A in session state. Hard gate — no subsequent phase may begin if root(A) is absent.
P-3
warrant
SARG-Ω
Audit all support relations for warrant bridges. Classify each unwarranted support as surface assertion. Report warrant_coverage ∈ [0,1]. A coverage of 0.0 halts the session — argument is structurally incoherent under INV-SARG-002.
P-4
defeat
SARG-Δ
Evaluate all proposed defeats by type (DT-001–DT-005). Apply recursion limit of 3 for DT-004. Classify failure modes DFM-001–DFM-005. Reclassify surface objections failing INV-SARG-003 as parallel assertions. Update N_A / R_A after successful defeats.
P-5
evaluate
SARG-Ρ
Execute all 5 evaluation gates EG-001–EG-005. Run reachability traversal post-defeat. Check independence condition for all evidence nodes. Flag reflexive paths. Gate failures produce structured violation reports for SARG-Σ.
P-6
catalogue
SARG-Σ
Synthesise gate results. Emit sarg_result ∈ {sound, defeasible, defeated, unsound}. Generate argument_templates handoff for Book 8 (NoS). Generate structural_argument_trajectory handoff for Book 9 (PD). Append session record to module catalogue.

GRL Integration

Book 6 (GRL) regime evaluation outputs feed directly into Book 7 SARG sessions. Fields from grl.regime_map — including authority measure α, enforcement cycle log, and regime_status_report — are ingested by SARG-Ν (NodeConstruct) as typed NT-002 Evidence nodes with provenance source: book6_grl.

Independence condition is satisfied when provenance(n_i) ∩ derivation_closure(root(A)) = ∅ — GRL-sourced evidence nodes are structurally independent of argument root claims constructed within the current SARG session.

Key Principle: SARG Soundness vs. Propositional Truth

Orthogonality Declaration

SARG soundness and propositional truth are orthogonal properties. A SARG-sound argument may contain false propositions; a propositionally valid syllogism may be SARG-unsound if it lacks structural warrant coverage or contains phantom nodes. Evaluators must not conflate propositional validity with SARG soundness, nor use propositional truth to override a SARG evaluation result.
