So RTT shouldn't say:

“RTT explains what caused Microsoft's outage.”

Rather:

“RTT provides a framework for characterizing the outage's stability, coupling, temporal recovery, and re-entry behavior.”

That's much stronger intellectually because we can test the model once Microsoft's post-incident report appears.

And, this could actually make a very nice TriadicFrameworks case study:

RTT Outage Analyzer
 Load → Coupling → Threshold → Collapse → Recovery → Re-entry → Coherence

We could run the November 12–13 Microsoft incident through it now, freeze the prediction/analysis, and later compare it against Microsoft's eventual root-cause report. That would turn RTT from retrospective storytelling into a genuinely falsifiable diagnostic exercise.
