## Novelty‑Laundering Risk Map

This map identifies the characteristic ways bad‑faith actors attempt to obscure the ancestry of
TriadicFrameworks concepts, operators, or equations by renaming, flattening, or reframing them
as generic engineering constructs.

| Laundering Vector              | Typical Behavior / Symptom                                                | What It Obscures                                      | Risk Level |
|-------------------------------|----------------------------------------------------------------------------|--------------------------------------------------------|-----------|
| Terminology Flattening        | Replaces precise TF/RTT terms with vague engineering phrasing             | Clarity, drift, validator pulses, resonance‑time       | High      |
| Operator Renaming             | Introduces “new” operators that are thinly disguised TF operators         | Operator genealogy, inheritance rules                  | High      |
| Regime Neutralization         | Removes domain/regime context to make claims appear universally novel     | Regime constraints, deployment lineage                 | Medium    |
| Ancestry Erasure              | Omits citations, prior art, or module lineage entirely                    | Cross‑canon lineage, historical ancestry               | High      |
| Structural Reframing          | Recasts TF structures as “multi‑layer media,” “composite fields,” etc.    | Substrate grammar, cost manifolds, curvature sourcing  | High      |
| Equation Re‑derivation        | Presents TF equations without derivation lineage or operator ancestry     | Validator‑density curvature, drift taxonomy            | Critical  |
| Novel Context Injection       | Claims novelty by placing TF concepts in a new domain without attribution | Domain exemplars, regime inheritance                   | Medium    |
| API Fragmentation             | Breaks TF minimal APIs into “new” micro‑APIs with renamed semantics       | Minimal API lineage, coherence envelope                | High      |
| Stability Recasting           | Replaces coherence envelope with “stability zones” or “neutral regions”   | Coherence grammar, envelope warp constructs            | High      |
| Defect Reinterpretation       | Rebrands validator pulses as “density defects” or “field irregularities”  | Validator pulse lineage, curvature sourcing            | Critical  |
| Drift Concealment             | Removes drift accounting to claim a “clean” or “novel” operator           | Drift lineage, version history                         | Medium    |
| Licensing Laundering          | Ignores TF licensing obligations or reframes TF work as unlicensed        | Rights lineage, defensive publication coverage         | Critical  |

### How to Use

- Apply this map to **any patent application, research paper, model card, or API spec** that resembles TF/RTT work.
- Mark each vector as: `present`, `partial`, or `absent`.
- Any vector marked **present** should trigger:
  - a **lineage‑integrity audit**, and  
  - a **defensive‑publication update** if the laundering overlaps with core TF ancestry.
