1. Practicum Purpose

The RTT/2 Instructor Practicum evaluates an instructor’s ability to:

  • teach Structural Detection at architectural scale
  • orchestrate multi‑module coherence in real time
  • diagnose system‑level contradictions
  • guide RTT/1 instructors through complex reasoning
  • design and run advanced practicum sessions
  • maintain zero drift under high cognitive load
  • demonstrate architectural clarity and lineage fidelity

This practicum is the experiential counterpart to the RTT/2 Architectural Mastery Exam.

2. Practicum Structure

The practicum consists of four experiential modules:

  1. Module A — Live Drift‑Envelope Architecture Teaching Demo
  2. Module B — Multi‑Module Coherence Orchestration Lab
  3. Module C — Instructor Mentorship & Pedagogical Architecture
  4. Module D — System‑Scale Collapse & Recovery Simulation

Each module contains required deliverables and evaluation criteria.

MODULE A — LIVE DRIFT‑ENVELOPE ARCHITECTURE TEACHING DEMO

A1. Teaching Task

Instructor must teach a 20–30 minute session covering:

  • drift geometry design
  • envelope geometry selection
  • deformation‑class escalation
  • continuity architecture
  • regime alignment logic

Audience: RTT/1 instructors.

A2. Required Demonstrations

Instructor must:

  • explain architectural constraints
  • demonstrate envelope transitions
  • show how drift and continuity interact
  • maintain zero drift in explanations
  • respond to live questions with structural clarity

A3. Evaluation Criteria

  • architectural clarity
  • operator correctness
  • envelope correctness
  • continuity correctness
  • regime correctness
  • pedagogical coherence

MODULE B — MULTI‑MODULE COHERENCE ORCHESTRATION LAB

B1. Orchestration Task

Instructor must run a live simulation involving:

  • Structural Detection
  • TEL
  • FFT
  • Opacity

B2. Required Demonstrations

Instructor must:

  • detect cross‑module contradictions
  • run harmonization cycles
  • regenerate TEL/FFT/Opacity packets
  • stabilize drift‑envelope transitions
  • explain system‑level reasoning

B3. Evaluation Criteria

  • contradiction detection accuracy
  • harmonization correctness
  • cross‑module alignment
  • synthesis stability
  • architectural reasoning clarity

MODULE C — INSTRUCTOR MENTORSHIP & PEDAGOGICAL ARCHITECTURE

C1. Mentorship Task

Instructor must mentor an RTT/1 instructor through:

  • a drift‑envelope misclassification
  • a regime‑shift misunderstanding
  • a continuity‑mapping error
  • a coherence‑break misidentification

C2. Required Demonstrations

Instructor must:

  • correct errors without drift
  • explain architectural reasoning
  • design a micro‑exercise to reinforce learning
  • demonstrate pedagogical architecture

C3. Evaluation Criteria

  • clarity of correction
  • pedagogical structure
  • zero‑drift guidance
  • architectural framing
  • student‑safe reasoning

MODULE D — SYSTEM‑SCALE COLLAPSE & RECOVERY SIMULATION

D1. Simulation Task

Instructor must run a full system‑scale simulation:

Type A → Type B → Type C → Type D → Collapse → Inversion → Type A

D2. Required Demonstrations

Instructor must:

  • classify each transition
  • identify collapse mode
  • diagnose break geometry
  • rebuild continuity
  • harmonize TEL/FFT/Opacity
  • regenerate synthesis packets
  • explain architectural flow

D3. Evaluation Criteria

  • system‑scale coherence
  • collapse diagnosis accuracy
  • recovery protocol correctness
  • cross‑module orchestration
  • architectural synthesis clarity
