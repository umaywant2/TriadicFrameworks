🌌 AI Training Findings 🌌¶

📖 Step‑by‑Step, Like a 5th Grader¶

  • corpus.txt
    👉 This is the “big book” you made. It’s just all your text files squished together into one giant scroll.
    Why? So the computer has one place to read from instead of hunting through hundreds of little files.

  • tokenize.py
    👉 This is the “dictionary maker.” It chops the big book into tiny word‑pieces (tokens) that the computer can understand.
    Why? Computers don’t read words like we do — they need everything broken into little puzzle pieces.

  • train.py
    👉 This is “school time.” You feed the tokens into the model so it can learn patterns, like how words follow each other.
    Why? Training teaches the computer to guess the next word, like finishing your sentence.

  • export_all.py
    👉 This is the “packing script.” It saves the trained model into different formats so you can use it later.
    Why? You don’t want to retrain every time — you want a ready‑to‑go backpack of knowledge.

  • greedy-loop.py
    👉 This is the “story writer.” It takes your trained model and asks it to keep guessing the next word over and over.
    Why? That’s how you make the model spit out text, like writing a paragraph or answering a question.

  • model-onnx.py
    👉 This is the “translator.” It converts your model into ONNX format, which is like a universal language for AI models.
    Why? ONNX makes it easier to run the model on different computers and tools.

  • run_dml_infer.py
    👉 This is the “test drive.” It runs the ONNX model using DirectML (a Windows tool that talks to your GPU).
    Why? To check if the model works fast on your graphics card.

  • export2directml.py
    👉 This is the “special exporter.” It saves the model in a way that DirectML likes best.
    Why? So Windows can use your GPU to run the model smoothly.

  • export2onnx.py
    👉 This is another “translator.” It saves the model into ONNX format again, maybe with different settings.
    Why? Because ONNX is the most portable format — you can share it or run it anywhere.

🎯 Big Picture¶

  1. Make a book (corpus.txt).
  2. Turn it into puzzle pieces (tokenize.py).
  3. Teach the computer (train.py).
  4. Save the knowledge (export scripts).
  5. Make it talk (greedy-loop.py).
  6. Translate it (ONNX/DirectML exporters).
  7. Run it fast (run_dml_infer.py).

    - At the end of each epoch, Hugging Face saves a checkpoint (model weights + optimizer state).

  3. Export the Model
    - Use export_all.py, export2onnx.py, or export2directml.py to save the trained model in portable formats.

    - DirectML = optimized for Windows GPU inference.
    - ✅ Action: run the export scripts to package your model.

  4. Inference / Generation
    - Test the model interactively with greedy-loop.py (text generation).

  5. Deployment / Integration
    - Once you’re happy, integrate the ONNX or DirectML model into your apps.
    - This is where you move from “training experiment” → “usable artifact.”
    - ✅ Action: wire the exported model into your pipeline or demo.

🧹 Step 1: WSL Choice¶

  • Do not skip WSL2.
  • WSL1 is legacy; it doesn’t support GPU/NPU acceleration.
  • WSL2 is required for DirectML, CUDA, ROCm, and the AI Toolkit.
  • ✅ Stick with WSL2 — it’s the only path that engages your RTX 3060, AMD iGPU, and NPU.

🎮 Step 2: GPU/NPU Drivers¶

  • NVIDIA RTX 3060 (via Oculink)
  • Install the latest NVIDIA drivers on Windows.
  • CUDA toolkit optional if you want native CUDA training.
  • AMD 890M iGPU
  • Update AMD drivers via Windows Update or OEM site.
  • ROCm is Linux‑native, but under WSL2 you’ll rely on DirectML for AMD acceleration.
  • NPU (Copilot+ Pro‑370)
  • NPU drivers are bundled with Windows 11 updates.
  • DirectML automatically dispatches workloads to NPU when available.

🐍 Step 3: Python Environment¶

  • Miniconda (recommended)
  • Install inside WSL2, not on Windows.
  • Create a clean environment for AI work:
    bash conda create --name aiwork python=3.10 -y conda activate aiwork
  • This avoids the “externally managed” system Python mess.
  • Why Conda?
  • It isolates dependencies.
  • You can nuke/recreate environments without touching system Python.

🔧 Step 4: Frameworks¶

  • PyTorch (training)
  • Install via Conda or pip inside your environment.
  • This is the stack you need for training — ONNX/DirectML alone won’t cut it.
  • torch-directml (inference)
  • Optional, if you want to test DirectML acceleration.
  • Install with:
    bash pip install torch-directml
  • ONNX Runtime (inference)
  • Install via Conda or NuGet (if using C#/C++).
  • Use for clean inference pipelines outside Python.

🧪 Step 5: Training vs. Inference¶

  • Training → PyTorch in Conda under WSL2.
  • Inference → ONNX Runtime + DirectML (clean, no Python packaging hell).
  • This way, you get both worlds: training capability and clean deployment.

  • ✅ Update drivers for RTX, AMD iGPU, and NPU.

⚡ Path B: Inference in Windows (AMD iGPU + NPU via DirectML)¶

  1. Stay in Windows (not WSL)

  2. Install ONNX Runtime (Windows)
    - For C#: via NuGet (Microsoft.ML.OnnxRuntime.DirectML).
    - For C++: download ONNX Runtime binaries.

    bash pip install onnxruntime-directml

  3. Run inference on AMD/NPU
    python import onnxruntime as ort sess = ort.InferenceSession("model.onnx", providers=["DmlExecutionProvider"]) print("Providers:", sess.get_providers())

✅ If you see DmlExecutionProvider, your AMD/NPU path is live.

🔄 Path C: Export Models (Bridge Training → Inference)¶

  1. Export PyTorch model to ONNX
    python import torch dummy = torch.randn(1, 3, 224, 224).cuda() torch.onnx.export(model, dummy, "model.onnx")

  2. Run exported model in ONNX Runtime (Windows)
    - This lets you train in WSL2 (RTX) and deploy in Windows (AMD/NPU).
    - Clean separation: training stack stays in Conda, inference stack stays in ONNX Runtime.

  • ✅ Export models from PyTorch → ONNX to bridge the two worlds.
  • ✅ This way, all three accelerators are engaged without chasing unsupported ROCm or broken Python packaging.

    def __init__(self):
        super(Net, self).__init__()
        self.fc1 = nn.Linear(28*28, 128)
        self.fc2 = nn.Linear(128, 10)

    def forward(self, x):
        x = x.view(-1, 28*28)
        x = torch.relu(self.fc1(x))
        return self.fc2(x)

net = Net().to(device)

# ⚙️ Optimizer + Loss

# 🔄 Training loop (1 epoch demo)

        inputs, labels = inputs.to(device), labels.to(device)

        optimizer.zero_grad()
        outputs = net(inputs)
        loss = criterion(outputs, labels)
        loss.backward()
        optimizer.step()

        if i % 200 == 0:
            print(f"Epoch {epoch}, Batch {i}, Loss: {loss.item():.4f}")
